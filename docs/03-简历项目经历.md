### 项目经历

#### 1. Agent 平台（LangGraph）｜ 独立开发 ｜ 2026.11 – 2026.12

**定位**：可评测、可观测、可降级的通用 Agent 运行时，同时作为 RAG 与 MCP 两个项目的内核。

**技术栈**：Python、FastAPI、LangGraph、SSE、Redis、Chroma、Langfuse、Prometheus / Grafana、Docker

- **状态图与工具层**：实现 intent → plan → tool-exec → reflect → replan → fallback 六状态图，明确终止条件与重规划触发；5 个工具（含副作用）统一 schema 注册、超时重试、幂等键与补偿；阅读 smolagents 循环机制与 LangGraph 图编排源码并输出分析，支撑状态机取舍。
- **流式与会话**：SSE 输出 thinking / tool_call / tool_result / answer 四类事件，处理 keep-alive 与断线重连；短期 messages + 摘要压缩 + 长期向量记忆，控制上下文长度与 token 成本。
- **降级与排障**：主备模型切换 + 错误分类（可重试 / 不可重试）+ 熔断；人为注入主模型超时与工具语义错误，基于 Langfuse trace 定位到具体节点，按「现象 → 证据 → 根因 → 修复 → 复测」完成复盘。
- **评测**：30 条分层用例（单工具 / 多工具 / 重规划 / 应拒答 / 故障注入），对比单 prompt、ReAct、原生 function calling、自研图四臂，统计任务成功率、平均步数、每成功任务 token 成本、P50/P95。
- **可观测**：Langfuse 为每个节点打 `@observe` span，降级链路可完整回放；Prometheus 暴露请求延迟、工具成功率、降级次数、token 消耗，配 Grafana 看板解释指标类型选择。

#### 2. RAG 评测系统 ｜ 独立开发 ｜ 2026.12 – 2027.01

**定位**：用消融实验回答 chunk / embedding / 检索 / rerank 的取舍，并作为检索工具接入 Agent 平台。

**技术栈**：Python、FastAPI、BM25、bge-m3、bge-reranker、Chroma、Langfuse、asyncio

- **检索链路**：自建 chunk → embed → 检索 → rerank 全链路；chunk（256 / 512 / semantic）× embedding（2 个）× 检索（向量 / BM25 / 混合 RRF）× rerank（有 / 无）共 36 组，复用 6 次建库，避免重复索引。
- **评测集与指标**：构建 50 条中文 query + ground truth，标注事实 / 比较 / 多跳 / 否定 / 长尾类型；以 Recall@5、MRR@10、P50/P95 为主指标，并把延迟拆成 embed / search / rerank 三段。
- **实验分析**：36 组结果落表，保留 3–5 个 badcase，按 query 类型分层定位掉点原因，输出「最优组合、原因与代价」的结论；阅读 pydantic-ai 类型约束与 Langfuse 数据模型，用于输出校验与观测字段设计。
- **接入 Agent**：作为检索工具接入项目 1，Langfuse 打 embed → search → rerank → generate span，拆分各段耗时并定位失败点。

#### 3. MCP 建站 Server ｜ 独立开发 ｜ 2027.01

**定位**：将内网生产验证过的建站机制独立重写为可公开演示的 MCP Server，可被 Claude Desktop 直接接入。

**技术栈**：Python、MCP Python SDK（FastMCP v3）、stdio + Streamable HTTP、API Key、Locust、Nginx、k3d / K8s、Docker

- **工具与协议**：实现 5 个真实工具，统一错误码（可重试 / 不可重试）、写操作幂等键与审计字段；工具描述写清何时用 / 何时不用、参数示例与返回结构；支持 stdio + Streamable HTTP 双 transport，HTTP 侧校验 Origin、默认绑定 127.0.0.1。
- **鉴权与治理**：API Key 常量时间比较、按 key 的 token bucket 限流并返回 Retry-After；审计日志记录 ts / key_id / tool / args_hash / duration / status。
- **公网演示**：Nginx 双 `server_name`（本地 + 临时公网域名）打通鉴权 → 工具调用全链路，手机流量验证可用，演示结束立即关闭入口。
- **压测与部署**：Locust 梯度加压找到 QPS 拐点，记录 RPS、P95 与施压端 CPU 水位；用 k3d 部署一次，梳理 Deployment / Service / Ingress 与 Compose 的映射；阅读 litellm 路由层与 dify `api/core/` 串联方式，用于网关与编排边界设计。

## 三、技术口径修正（投递与面试统一）

1. **MCP transport 写 Streamable HTTP，不写 SSE**：HTTP+SSE 自 `2025-03-26` 起废弃，当前是 stdio + Streamable HTTP。简历、GitHub README、面试口述保持一致，否则会被判为看旧资料。
2. **FastMCP 锁 v3 小版本**：v2 的 transport 注册与生命周期写法大量弃用，README 注明版本。
3. **评测四臂，不是三臂**：只打 ReAct 是打稻草人，真正的主基线是原生 function calling；四臂对比才能回答「自研图多花的成本换来了多少成功率」。
4. **RAG 补 P95 与三段延迟**：只看 P50 会掩盖长尾；embed / search / rerank 分开计时，才能解释性能差异来自哪一段。
5. **公网演示是临时入口**：只暴露演示服务、必须鉴权、用完立即关闭；不映射任何内网系统，不在简历写具体域名或端口。

**三条最强面试故事**：

1. **确认绕过**：Agent 可以自己填 `confirmed=true`，所以把确认从 MCP 工具里物理移除，安全边界从「模型行为」下沉到「进程边界」。
2. **无 MQ 的异步评审**：状态机 + worker + 调度兜底，概念上等价于队列，但不需要 Kafka / Celery；未来只替换唤醒实现即可迁移。
3. **断连后的 token 燃烧**：`GeneratorExit` 分支显式 `aclose()` 上游流，客户端一断开就停止计费，而不是等 300s 超时。
